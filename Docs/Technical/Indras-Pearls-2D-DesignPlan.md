# 2D Indra's-Pearls Renderer — Design Plan

**Tracking issue:** [#888](https://github.com/AloneButUnsober/FracturingFog/issues/888)
(part of frontier epic [#850](https://github.com/AloneButUnsober/FracturingFog/issues/850)).
**Status:** design doc — *no code lands until this doc is reviewed and the sliced
sub-issues are filed.*

**Why this exists (the re-home).** Split out of the 3D Kleinian epic after a scope
finding ([Kleinian-Generalization-DesignPlan.md](Kleinian-Generalization-DesignPlan.md)
§3.4, issue #877): **Grandma's-recipe** and **Maskit-slice** groups are
**complex-Möbius (2D) constructions** — their limit set is a fractal *curve* on the
Riemann sphere Ĉ, **not** a 3D solid — so they cannot be rendered by the 3D
distance-estimator (`KleinianCalculator`). They belong to a dedicated **2D
point/curve plotter**, which this doc plans. The marquee **Maskit-slice animation**
(formerly Kleinian S6 / #879) rides *this* renderer.

**Related docs:** [Theoretical-Fractal-RnD.md](Theoretical-Fractal-RnD.md) §2.3 (the
2D Indra's Pearls candidate); [Resources-Bibliography.md](../Resources-Bibliography.md).

## 1. Purpose & scope

Render the **limit set of a two-generator Kleinian group** of complex Möbius
transformations — the classic *Indra's Pearls* imagery — as a 2D plane fractal,
with the **Grandma's-recipe** trace parameterization and the **Maskit slice** as
the group-selection surface, and an **animation** sweeping the trace toward the
slice boundary (the "group degenerating into a limit curve").

**In scope:**
- Two-generator Möbius groups via Grandma's recipe (traces `ta, tb, tab`).
- The Maskit slice (a one-complex-parameter family `μ`) as a simpler entry point.
- A limit-set plotter (word enumeration → plane), Zoomable2D.
- Colouring by word length / generator parity.
- The Maskit/trace animation.

**Out of scope (explicitly):**
- The **3D** Kleinian solid renderer — that is the shipped `KleinianCalculator`
  (sphere-inversion DE); this is a *different* render path and FractalType.
- General *n*-generator groups, higher-genus surface groups, quasi-Fuchsian
  deformation theory beyond the two-generator slice (later, if ever).
- Escape-time / distance-estimator anything — this is **combinatorial**.

---

## 2. What ships today (precedents to build on)

There is **no complex-Möbius group renderer** in FF. But two shipped calculators
are close structural templates:

- **`ApollonianCalculator`** — the closest. A 2D **limit set of circle inversions**
  (Descartes/Vieta recursion), `System.Numerics.Complex`-based, recursive
  enumeration with a **depth + sub-pixel-radius stop**, **`SupportsZoomPan`** so
  pan/zoom transforms the primitives and deeper recursion auto-reveals on zoom
  (Zoomable2D). The Indra's-Pearls renderer is the *same shape* with Möbius-word
  enumeration in place of Descartes/Vieta. **Model the new calculator on this one.**
- **`IFSCalculator`** — chaos-game: pick a map, apply to a point, increment a
  density buffer, colour by hit count. A fallback rendering strategy (stochastic
  forward orbits) if deterministic enumeration proves fiddly.

Neither renders a Möbius group; both establish the "non-escape-time 2D plotter"
pattern, the `Complex` usage, and (Apollonian) the zoomable-limit-set contract.

## 3. Math foundations (Rule B — cite everything)

### 3.1 Möbius transformations and the group

A **Möbius transformation** of the Riemann sphere Ĉ = ℂ ∪ {∞} is
`g(z) = (az + b)/(cz + d)`, `ad − bc = 1`, represented by a matrix
`[[a, b], [c, d]] ∈ SL(2, ℂ)` (up to sign, `PSL(2, ℂ)`). Composition = matrix
product. A two-generator group `⟨a, b⟩` is generated by two such matrices and
their inverses; the alphabet is `{a, A, b, B}` with `A = a⁻¹`, `B = b⁻¹`.

### 3.2 Limit set

The **limit set** Λ is the set of accumulation points of the group orbit — the
closure of the repelling fixed points of the loxodromic elements. For a discrete
(Kleinian) two-generator group it is a fractal: a Cantor set, a circle, or (at the
interesting boundary) a space-filling-ish **limit curve**. Λ is what we plot. It is
1-dimensional-ish (Hausdorff dim between 1 and 2), which is exactly why it does not
fit the 3D solid DE.

### 3.3 Grandma's recipe (the parameterization)

Mumford–Series–Wright give an explicit recipe producing the two generator matrices
from three complex **traces** `ta = tr(a)`, `tb = tr(b)`, `tab = tr(ab)` satisfying
the **Markov identity** `ta² + tb² + tab² = ta·tb·tab`. "Grandma's recipe" solves
for `a, b` given `(ta, tb, tab)`; this is the canonical Indra's-Pearls parameter
space (MSW ch. 8). Special cases:
- `ta = tb = 2`: parabolic commutator — the **cusp** groups.
- The **Maskit slice**: set `ta = 2` (one generator parabolic) and parameterize by
  a single complex `μ` with `b = [[−iμ, −i], [−i, 0]]`, `a = [[1, ?], [?, 1]]`
  (MSW ch. 9) — a one-parameter family whose boundary is the **Maskit slice
  boundary**, the marquee animation target.

### 3.4 Rendering the limit set — enumeration algorithms

Two families (pick per §4):

- **DFS "special words" boundary tracing (MSW ch. 9 algorithm).** Walk the group
  word-tree depth-first, tracking a repelling fixed point per branch; descend until
  successive fixed points are within one pixel (the branch has converged onto Λ),
  then plot and backtrack. Produces the limit set as an ordered **curve** (connect
  successive fixed points) — the crisp Indra's-Pearls line drawings. The stopping
  test uses the **cusp / commutator** structure (MSW's `epsilon` on fixed-point
  separation). This is the *right* algorithm for the beautiful curve renders.
- **BFS depth-capped orbit plot.** Enumerate all reduced words up to length *n*
  (no immediate back-tracking `aA`, `bB`), apply each to a seed point (a fixed
  point of a generator), plot the images as a **point cloud / density buffer**.
  Simpler, robust, but blurrier; a good S1 first cut before the DFS curve tracer.

**Numerical note:** long words = long matrix products → precision loss; entries
grow exponentially. Normalize matrices (divide by √det, or periodically) and cap
word length. Deep zoom needs **re-enumeration at higher depth**, not perturbation
(the FF deep-zoom perturbation engine does not apply — combinatorial, not
iterative). Apollonian's "recurse until sub-pixel" contract is the model.

### 3.5 Group families / presets

| Preset | Parameters | Limit set | Ref |
|--------|-----------|-----------|-----|
| Maskit slice | single `μ` | parabolic-comm limit curve; `μ = 2` = the "apple" | MSW ch. 9 |
| Grandma's-recipe general | `ta, tb, tab` (Markov) | Cantor set → circle → curve | MSW ch. 8 |
| Riley slice | real/complex `c`, two parabolics | two-parabolic-generator groups | Riley; MSW |
| Cusp groups (rational `p/q`) | boundary cusps | the "necklace" limit curves | MSW ch. 9–10 |

The Maskit slice is the cleanest S1/animation target (one parameter, a known
boundary to animate toward).

## 4. Design — data model, render path, decision

### 4.1 Decision: a **new 2D `FractalType`**, Apollonian-modeled, Zoomable2D

- **New `FractalType.IndrasPearls`** (2D). Unlike the 3D Kleinian re-home decision
  (extend the existing type), here there is **no existing 2D type** to extend and
  the render path is genuinely new (combinatorial word enumeration), so a new type
  is warranted. Follow the **new-2D-calculator registration checklist** (~13 sites;
  template = `ApollonianCalculator` / `RandomTile` / `ChaoticBilliard`).
- **Motion class Zoomable2D** (like Apollonian) — the limit set is a self-similar
  plane fractal; zoom reveals deeper words. `SupportsZoomPan = true`; deeper
  enumeration auto-reveals on zoom (Apollonian contract).
- **Not NonSpatial** (unlike DLA/Buddhabrot): the plane *is* the fractal, so pan/zoom
  is meaningful and the video slideshow gets a real zoom leg.

### 4.2 Data model

```
IndrasGroupFamily (enum): Maskit | GrandmaRecipe | Riley
+ params:
    MaskitMu (complex: two doubles)                — Maskit
    GrandmaTa, GrandmaTb, GrandmaTab (complex ×3)  — GrandmaRecipe (Markov-constrained)
    MaxWordDepth (int)                              — enumeration cap
    RenderMode (enum): CurveTrace | PointCloud
```

A small `Mobius` value type (four `Complex`: a, b, c, d; multiply, inverse,
normalize, fixed points, apply-to-point) is the core primitive — lives in the
Engine calculator (or Abstractions if it must be serialized; params are scalars, so
the matrices are *derived*, not stored). Grandma's recipe is a pure function
`(ta, tb, tab) → (Mobius a, Mobius b)`.

### 4.3 Render path

`ApollonianCalculator`-style: transform the plane by `(CenterX, CenterY, Zoom)`,
enumerate words (DFS curve-trace or BFS point-cloud), map each plotted limit-set
point to a pixel, write the colour buffer. Colour by word length / last generator
(density for point-cloud; per-segment for curve). Depth/pixel-size stop.

## 5. Toolchain reach (Rule A)

- **CalcGen / DSL — out of reach, by construction.** Both DSLs compile a per-pixel
  `f(z, c)` iteration; there is no vocabulary for group-word enumeration or Möbius
  matrix products. Recorded so it is not re-litigated. (Same conclusion as the 3D
  Kleinian.) The closest existing analogue is the **IFS chaos-game / L-system**
  word path, not the expression DSL.
- **ColorGen / Color Theme — in reach.** Colour by **word length** or **generator
  parity / last-letter** → a **Categorical `ColorThemeKind`** (the billiard
  `gateId` / chaotic-scattering precedent, #626; same idea as the 3D Kleinian S5
  colour driver #878). Surface a per-plotted-point integer AOV (word length,
  last generator). ColorGen palettes apply unchanged.

## 7. Risks & open questions

- **Word-tree explosion.** The reduced-word count grows ~3ⁿ. BFS to depth *n* is
  bounded but large; DFS with a good sub-pixel stop is the scalable path. Hard
  `MaxWordDepth` cap always.
- **Numerical precision of long matrix products.** Entries grow exponentially;
  normalize (÷√det) and cap depth. Near the Maskit boundary (near-degenerate
  groups) fixed points are ill-conditioned — validate against MSW reference plates.
- **Deep zoom.** No perturbation path — zoom = re-enumerate deeper (Apollonian
  model). Fine, but each zoom is a full recompute; acceptable (Apollonian does
  this).
- **DFS stopping correctness.** The MSW special-words algorithm has subtle
  termination (cusp detection); getting it right is S3's main risk — hence S1 ships
  the robust BFS point cloud first, and S3 layers the curve tracer.
- **Validation (Bucket II mitigation).** Grandma's recipe + Maskit slice have
  **abundant reference imagery** (MSW plates) — unlike the FF-original dual-orbit
  map, validation here is *easy*: match the book's pictures.
